# YouGram plugin store

Каталог собирается автоматически из GitHub Releases. Руками `index.json` не правится.

```
Release + файл .ygplugin ─► GitHub Action (tools/build_index.py) ─► site/index.json + site/icons/
                                                                          │ commit в main
                                                                          ▼
                                                      Cloudflare Pages раздаёт site/ (+ страница каталога)
Приложение: INDEX_URL = https://<проект>.pages.dev/index.json, файлы плагинов качаются с GitHub Releases
```

## Выпуск плагина
1. В `manifest.json`: `"api": "2.3"` (или любая более новая версия, минимум 2.1), `"icon": "icon.png"`, поднятая `version`.
   Необязательно: `"category"`, `"long_description"` (каталог их подхватит).
2. `python pack.py <папка_плагина> <id>-<version>.ygplugin`
3. GitHub → Releases → Draft a new release → тег (любой, например `hello-2.1.0`) →
   текст релиза станет «Что нового» → прикрепи `.ygplugin` → **Publish release**.
4. Через минуту во вкладке Actions пройдёт «Build plugin index», затем Cloudflare выкатит сайт.

В каталог попадает самая новая версия каждого `id`. Пре-релизы и черновики пропускаются.
Удалил релиз — плагин пропал из каталога после пересборки.

## Что проверяет сборщик (остальное пропускается с предупреждением в Actions)
manifest.json в корне; корректные id и version; API 2.1 и новее (верхней границы нет, формат MAJOR.MINOR); есть `lib/<abi>/<entry>`;
не больше 200 файлов; нет `..` и абсолютных путей; иконка png/webp/jpg до 512 КБ;
sha256 считается по скачанному файлу и сверяется с данными GitHub; пакет до 64 МБ.
Сбой сети при скачивании останавливает сборку, каталог при этом не затирается.

## Безопасность
Плагин содержит нативный код и выполняется у всех пользователей. Публиковать релизы
может любой участник с правом записи в репозиторий, поэтому: давай write-доступ только
доверенным людям и включи 2FA. Репозиторий должен быть **публичным**, иначе приложение
не скачает файл без авторизации.

## Вход через GitHub и обновления через сайт
Сайт и API раздаёт один Cloudflare Worker (`tools/worker.js`, настройки в `wrangler.toml`).
Автор входит через GitHub, загружает `.ygplugin`, воркер читает `manifest.json` и кладёт файл
ЧЕРНОВИКОМ релиза с меткой владельца. Ты нажимаешь Publish, `build_index.py` пересобирает каталог.

- Новый `id` -> «Новый плагин», владельцем станет тот, чей релиз ты опубликуешь первым.
- Существующий `id` -> «Обновление»: только владелец (или логин из `ADMINS`), версия должна быть выше текущей.
- Владельцы лежат в `site/owners.json` (собирается автоматически). Релизы, выложенные тобой руками без метки, принимаются всегда.
- Через сайт до 32 МБ, больше только через GitHub Releases.

Настройка один раз:
1. GitHub -> Settings -> Developer settings -> OAuth Apps -> New. Callback URL: `https://<воркер>.workers.dev/api/auth/callback`. Client ID вписать в `wrangler.toml` (`GH_CLIENT_ID`).
2. `npx wrangler secret put GH_CLIENT_SECRET`, `SESSION_SECRET` (любая длинная случайная строка), `GITHUB_TOKEN` (fine-grained токен, Contents: write только на этот репозиторий).
3. `npx wrangler deploy`. Чтобы сайт обновлялся после пересборки каталога, подключи репозиторий в Cloudflare (Workers & Pages -> воркер -> Settings -> Builds). `pages.yml` удали.

## Публикация без ручной проверки
`AUTO_APPROVE` в `wrangler.toml`: `off` (всё черновиком, ты жмёшь Publish), `updates` (обновления сразу, новые плагины вручную), `all` (всё сразу).
Админы из `ADMINS` публикуются сразу при любом режиме. При `all` новые плагины от GitHub-аккаунтов младше `MIN_ACCOUNT_DAYS` дней идут на ручную проверку.
`BANNED` закрывает публикацию логину. Чтобы убрать вредный плагин, удали его релиз на GitHub: после пересборки он исчезнет из каталога.
Плагин содержит нативный код и запускается у пользователей, поэтому `updates` безопаснее, чем `all`.
